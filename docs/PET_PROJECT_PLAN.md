## Принятый формат

Backend создаёт ученик. Тренер помогает определить контракт и критерии, объясняет новое на отдельном примере, предоставляет независимые тесты и полностью проверяет очередной результат. Один активный этап; переход дальше после его проверки. Готовые классы, конфигурация, SQL-схема и заготовки приложения за ученика не создаются.

Документы первой версии подготовлены; конкретный каталог и детали MVP уточняются. Следующая последовательность — рамка работы, окончательные контракты задаются на проектных этапах.

## Этап 0 — небольшая первая версия

Определить, для кого приложение, какую задачу решает и какие 2–3 сценария входят в первую версию. Выбрать один сценарий для первого этапа. Записать ограничения и то, что остаётся за пределами первой версии.

Результат: краткое описание MVP, роли пользователей, первый сценарий, входные данные, наблюдаемый результат и критерии приёмки. Проектирование не требует предварительно проходить OAuth, весь углублённый SQL или CI/CD.

## Этап 1 — один законченный сценарий

Самостоятельно собрать проект и реализовать путь HTTP-запрос → проверка → бизнес-операция → PostgreSQL → ответ. Создать миграцию и тесты для обычного случая, границ и ошибок. Точные endpoint, поля, статусы и ограничения определяются выбранным сценарием.

Результат: воспроизводимый запуск одного полезного сценария и успешные проверки его контракта; краткий README с командами.

## Этап 2 — первая версия целиком

Последовательно добавить оставшиеся сценарии MVP, нужные связи данных и бизнес-ограничения. Транзакции, авторизацию, конкуренцию и индексы вводить там, где сценарий требует их применения. Каждый шаг проверять отдельно.

Результат: все согласованные сценарии первой версии работают и покрыты проверками. Новый функционал не добавляется бесконечно вместо завершения версии.

## Этап 3 — качество и запуск

По мере развития проекта добавить CI на его собственные тесты, описание API, логирование и Docker Compose. Когда первая версия готова — развернуть учебное окружение и проверить запуск. Эти работы могут выполняться раньше, когда полезны текущему этапу.

Результат: другой человек может запустить и проверить приложение по документации; опубликованная версия проходит CI и доступна в выбранном окружении, если развёртывание входит в согласованную первую версию.

## Следующие возможности

OAuth 2.0 / OpenID Connect, сложные SQL-отчёты, обработка конкурентных изменений и дальнейшие технологии добавляются по потребностям проекта или как отдельные учебные улучшения после первой версии. Они не задерживают начало работы.
