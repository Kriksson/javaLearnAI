# Задача №64 — Самостоятельный мини-проект: API каталога квестов

**Сложность:** мини-проект, базовый Spring.

**Практика:** самостоятельно спроектировать классы и связи, разделить HTTP-слой и логику, создать сервисы и подключить Spring-компоненты аннотациями.

**Впервые:** `@Repository` для компонента, который хранит и выдаёт данные; проектирование небольшого приложения по слоям.

## Материал

Spring находит классы-компоненты в пакете приложения и создаёт их. `@Repository` отмечает источник данных, `@Service` — бизнес-логику, `@RestController` — HTTP-обработчик. Если зависимость передана через конструктор, Spring сам создаёт нужный объект и связывает слои.

Независимый пример: `/health` возвращает состояние из хранилища через сервис и контроллер.

```java
import org.springframework.stereotype.Repository;
import org.springframework.stereotype.Service;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@Repository
class StatusStore {
    String readStatus() {
        return "online";
    }
}

@Service
class StatusService {
    private final StatusStore store;

    StatusService(StatusStore store) {
        this.store = store;
    }

    String getStatus() {
        return store.readStatus();
    }
}

@RestController
class StatusController {
    private final StatusService service;

    StatusController(StatusService service) {
        this.service = service;
    }

    @GetMapping("/health")
    String health() {
        return service.getStatus();
    }
}
```

- `@Repository`, `@Service` и `@RestController` регистрируют три роли как Spring-компоненты.
- Конструкторы показывают зависимости: сервис использует хранилище, контроллер использует сервис.
- `@GetMapping` связывает `GET /health` с методом `health`.
- Пример можно поместить в один файл: классы не объявлены `public`. В проекте задачи размести каждый самостоятельный класс в отдельном `.java`-файле.

## Спроектируй и собери приложение

Создай небольшой API каталога квестов. Сам выбери классы и их связи так, чтобы контроллер, сервис и репозиторий имели отдельные роли. Отдельный документ с планом писать не нужно.

Данные каталога заранее определены:

| ID | Название | Сложность |
|---:|---|---|
| 1 | Лесной патруль | `EASY` |
| 2 | Пещера гоблинов | `NORMAL` |
| 3 | Башня мага | `HARD` |

Сам выбери названия классов и внутренние сигнатуры. В проекте должны быть следующие роли:

- компонент с `@Repository`, который хранит начальный каталог и ищет квесты;
- один `@Service`, который через конструктор получает репозиторий, выдаёт список и ищет квест по ID;
- компонент с `@RestController`, который принимает HTTP-запросы и формирует статусы ответов;
- enum сложности с размером награды, модель квеста и модель HTTP-ответа о награде. Используй `record` там, где объект не должен менять состояние.

Связывай контроллер, сервис и репозиторий через конструкторы. Контроллер не должен хранить каталог или рассчитывать награду. Хранилище в памяти: база данных не нужна.

### Правила расчёта награды

Размер награды — неизменное свойство сложности, поэтому храни его в enum, а не в отдельном сервисе. Репозиторий хранит квесты с ID, названием и сложностью; сервис получает квест, а число монет берёт у его сложности.

| Сложность | Монеты |
|---|---:|
| `EASY` | 40 |
| `NORMAL` | 75 |
| `HARD` | 120 |

Правило точное: `coins` равен числу в таблице для сложности квеста; множителей и случайных бонусов нет. Если квест не найден, основной сервис возвращает `Optional.empty()`. Контроллер преобразует найденный результат в `200`, а пустой — в `404` без тела.

## HTTP-контракт

- `GET /quests` → `200` и массив всех квестов в порядке ID. Каждый объект содержит `id`, `name`, `difficulty`.
- `GET /quests/{questId}` → `200` и объект квеста с этими же тремя полями; неизвестный ID → `404` без тела.
- `GET /quests/{questId}/reward` → `200` и объект `{ "questId": 2, "questName": "Пещера гоблинов", "coins": 75 }`; неизвестный ID → `404` без тела.
- Если вместо числа в ID передан текст, например `/quests/abc`, верни `400 Bad Request`.

## Примеры

- `GET /quests` → три квеста, отсортированных по ID.
- `GET /quests/1` → `200`, `{"id":1,"name":"Лесной патруль","difficulty":"EASY"}`.
- `GET /quests/3/reward` → `200`, `{"questId":3,"questName":"Башня мага","coins":120}`.
- `GET /quests/99/reward` → `404`, пустое тело.
