# Задача №43 — Перевод монет через JDBC

**Сложность:** средняя

**Закрепляем:** JDBC `PreparedStatement`, параметризованный `UPDATE`, `executeUpdate()`, валидацию и `SQLException`.

**Новое:** транзакции JDBC: `setAutoCommit(false)`, `commit()` и `rollback()`.

Реализуй перевод монет между двумя кошельками. Списание и зачисление должны произойти вместе: если второй шаг не удался, первый тоже отменяется.

## Материал для изучения

По умолчанию JDBC обычно подтверждает каждую SQL-команду отдельно (`autoCommit = true`). Для нескольких связанных изменений отключи автоподтверждение, выполни команды и затем:

- `commit()` — сохранить все изменения;
- `rollback()` — отменить изменения с начала транзакции.

После завершения операции верни соединению исходный режим автоподтверждения. В этой задаче метод принимает только соединение с включённым `autoCommit`; чужую уже начатую транзакцию нельзя подтверждать своим `commit()`.

Количество изменённых строк возвращает `executeUpdate()`. Если условный `UPDATE` изменил 0 строк, нужного кошелька нет или списать монеты нельзя. Тогда откати транзакцию и верни `false`.

## Что сделать

В `src/main/java/learning/task043/CoinTransferService.java` реализуй:

```java
public CoinTransferService(Connection connection)
public boolean transfer(int fromPlayerId, int toPlayerId, int amount) throws SQLException
```

Таблица `player_wallets` содержит `player_id` и `coins`. Баланс каждого кошелька — от 0 до 100 включительно; это ограничение проверяет база.

- Конструктор сохраняет соединение, для `null` выбрасывает `IllegalArgumentException`.
- Перед SQL проверь: оба ID положительны и различаются, `amount > 0`. Иначе выбрось `IllegalArgumentException` без изменения данных.
- Если у соединения уже выключен `autoCommit`, выбрось `IllegalStateException`, не меняя его режим и данные.
- Переведи монеты двумя параметризованными `UPDATE`: спиши сумму только при достаточном балансе отправителя, затем зачисли получателю.
- Верни `true` и зафиксируй транзакцию, только если оба `UPDATE` изменили по одной строке.
- Если отправителя нет, средств не хватает или получателя нет, откати изменения и верни `false`.
- При `SQLException` откати изменения и передай ошибку вызывающему коду. После операции восстанови `autoCommit`; соединение не закрывай.

## Примеры

Исходные балансы: игрок 1 — 100, игрок 2 — 50, игрок 3 — 0.

- `transfer(1, 2, 30)` → `true`; балансы 70, 80, 0.
- `transfer(1, 2, 101)` → `false`; балансы не меняются.
- `transfer(1, 2, 60)` → `SQLException`: у игрока 2 получилось бы 110, база отклонит зачисление; все балансы останутся прежними.

## Ограничения и готовность

- Не делай два независимых изменения без транзакции.
- Используй `PreparedStatement` и закрывай JDBC-ресурсы; оставляй переданный `Connection` открытым.
- Тесты проверяют обычный перевод, перевод всей суммы, недостаток средств, отсутствие кошелька, ошибку при зачислении, неверные аргументы и восстановление `autoCommit`.
- Новые зависимости не нужны.
