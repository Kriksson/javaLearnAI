9# Задача №9: боевые классы персонажей

- Сложность: высокая
- Закрепление: отдельные классы, инкапсуляция, состояние объекта, условия и исключения
- Новые навыки: наследование, `extends`, `super`, `@Override` и полиморфные вызовы

## Контекст

Базовый класс `GameUnit` уже готов. Он хранит имя и здоровье, принимает урон и содержит стандартные методы силы атаки и описания.

Реализуй два отдельных дочерних класса: `Warrior` и `Mage`.

## `Warrior`

```java
public Warrior(String name, int armor)
public int getArmor()
```

Требования:

- класс наследуется от `GameUnit`;
- конструктор вызывает `super(name, 120)`;
- броня допустима в диапазоне `0..20`, иначе выбрасывается `IllegalArgumentException`;
- `getAttackPower()` переопределён и возвращает `18`;
- `takeDamage(int damage)` уменьшает входящий урон на величину брони, но итоговый урон не может быть отрицательным;
- отрицательный исходный урон вызывает `IllegalArgumentException`;
- `getDescription()` возвращает строку `Имя [WARRIOR], HP: здоровье, armor: броня`.

Пример: воин с бронёй `5` получает `20` урона и теряет `15` здоровья.

## `Mage`

```java
public Mage(String name)
public int getMana()
public boolean castSpell(GameUnit target)
public void restoreMana(int amount)
```

Требования:

- класс наследуется от `GameUnit`;
- конструктор вызывает `super(name, 80)` и устанавливает `30` маны;
- `getAttackPower()` переопределён и возвращает `10`;
- `castSpell` тратит `10` маны, наносит цели `25` урона и возвращает `true`;
- если маны меньше `10`, метод ничего не меняет и возвращает `false`;
- `restoreMana` принимает только положительное число и восстанавливает ману максимум до `30`;
- `getDescription()` возвращает строку `Имя [MAGE], HP: здоровье, mana: мана`.

Аргумент `target` не равен `null`.

## Полиморфизм

Следующий код должен вызывать переопределённые методы дочернего класса:

```java
GameUnit unit = new Warrior("Tank", 5);
unit.getAttackPower(); // 18
unit.getDescription(); // Tank [WARRIOR], HP: 120, armor: 5
```

## Ограничения

- `GameUnit`, `Warrior` и `Mage` находятся в отдельных файлах.
- Поля дочерних классов должны быть `private`.
- Не изменяй `GameUnit` и публичные сигнатуры.
- Переопределённые методы помечай `@Override`.

## Критерии готовности

- Оба класса действительно наследуются от `GameUnit`.
- Конструкторы правильно вызывают базовый конструктор.
- Воин учитывает броню при получении урона.
- Маг расходует и восстанавливает ману.
- Переопределённые методы работают через переменную типа `GameUnit`.
- Все тесты проходят.
