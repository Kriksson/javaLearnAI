# Задача №65 — Самостоятельный мини-проект: доска заявок гильдии

**Сложность:** мини-проект, базовый Spring.

**Практика:** самостоятельно спроектировать модель, роли компонентов и связи между ними; собрать рабочий REST API на Spring Boot.

**Закрепи:** `@Repository`, `@Service`, `@RestController`, конструкторное внедрение, `record`, `enum`, Bean Validation, `ResponseEntity`, `MockMvc`.

**Новый нюанс HTTP:** ответ `201 Created` обычно указывает адрес созданного ресурса в заголовке `Location`.

## Короткий пример: `201 Created` и `Location`

```java
import java.net.URI;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
class PingController {
    @PostMapping("/pings")
    ResponseEntity<PingResponse> createPing() {
        URI location = URI.create("/pings/7");
        return ResponseEntity.created(location).body(new PingResponse("saved"));
    }
}

record PingResponse(String state) {
}
```

- `URI.create(...)` задаёт адрес ресурса, который создали.
- `ResponseEntity.created(location)` формирует статус `201` и заголовок `Location`.
- `.body(...)` добавляет JSON-тело ответа.

Это пример для отдельного `/pings` endpoint, не часть доски заявок.

## Проект

Сделай API доски заявок, где игроки публикуют поручения, а герои могут взять каждое поручение только один раз.

Сам выбери классы, названия методов и связи. Зафиксированы только роли и HTTP-контракт:

- `@Repository` хранит заявки в памяти, создаёт уникальные положительные ID и находит заявку по ID;
- один `@Service` получает репозиторий через конструктор, создаёт заявки и применяет правило взятия заявки;
- `@RestController` получает сервис через конструктор, принимает запросы и выбирает HTTP-статусы;
- HTTP-модели отделены от внутреннего хранения; статус заявки удобно представить через `enum`.

Отдельный `ARCHITECTURE.md` или другой документ проектирования не нужен. Объясни выбранные роли и связи в коде.

### Данные и правила

- Новая заявка содержит `title` длиной от 1 до 80 символов и `reward` от 1 до 10 000 монет включительно.
- После создания заявка имеет статус `OPEN`, поле `claimedBy` равно `null`.
- Имя героя для взятия заявки должно содержать от 1 до 40 непробельных символов.
- Заявку со статусом `OPEN` можно взять один раз. При успехе статус становится `CLAIMED`, а `claimedBy` сохраняет имя героя.
- Повторное взятие возвращает `409 Conflict`; первый герой и состояние заявки остаются без изменений.
- Хранилище работает только в памяти; после перезапуска данные сбрасываются.

### HTTP-контракт

- `POST /guild/requests` с JSON `{ "title": "Сопроводить караван", "reward": 90 }` создаёт заявку: `201 Created`, заголовок `Location: /guild/requests/{id}` и JSON с полями `id`, `title`, `reward`, `status`, `claimedBy`.
- `GET /guild/requests` возвращает `200` и все заявки в порядке возрастания ID; пустой каталог — пустой массив.
- `GET /guild/requests/{id}` возвращает `200` и заявку; неизвестный ID — `404` без тела.
- `PUT /guild/requests/{id}/claim` с JSON `{ "heroName": "Лира" }` для открытой заявки возвращает `200` и обновлённую заявку.
- повторное взятие возвращает `409` без тела; неизвестный ID — `404` без тела.
- пустые, слишком длинные или некорректные поля JSON возвращают `400`. Нечисловой ID также возвращает `400`.

### Примеры

- Создание заявки на 90 монет возвращает `201`, `Location: /guild/requests/1` и объект со статусом `OPEN`.
- `PUT /guild/requests/1/claim` с `{"heroName":"Лира"}` возвращает `200` и `{"status":"CLAIMED","claimedBy":"Лира"}` вместе с остальными полями.
- Попытка другого героя взять ту же заявку возвращает `409`; в заявке остаётся первый герой.

## Готовность

- Все роли связаны через Spring и конструкторное внедрение; контроллер не хранит каталог и не решает бизнес-правило взятия заявки.
- Ограничения запроса проверяются Bean Validation.
- Тесты покрывают создание и заголовок `Location`, список и его порядок, чтение по ID, успешное и повторное взятие, отсутствие заявки, границы полей и неверный формат ID.
- Используй зависимости, уже подключённые в проекте. База данных и новые библиотеки не нужны.
