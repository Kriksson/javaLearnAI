# Парсер карточки персонажа

- Задача: №4
- Навыки: разбор структурированной строки и проверка формата
- Сложность: высокая

## Условие

Сервер присылает данные персонажа одной строкой:

```text
ник|класс|уровень
```

Нужно проверить строку, извлечь три поля и создать карточку персонажа.

### `normalizeToken`

Метод должен:

1. убрать пробелы по краям;
2. перевести текст в верхний регистр;
3. заменить каждый пробел символом `_`;
4. вернуть полученную строку.

### `createCharacterCard`

Метод должен:

1. убедиться, что строка содержит ровно два разделителя `|`;
2. найти их позиции через `indexOf` и `lastIndexOf`;
3. извлечь поля через `substring`;
4. обработать ник и класс методом `normalizeToken`;
5. убрать пробелы по краям уровня;
6. вернуть `Некорректные данные`, если структура неверна или любое поле пусто;
7. вернуть карточку в формате `[КЛАСС] НИК (уровень УРОВЕНЬ)`.

## Сигнатуры

```java
public static String normalizeToken(String value)
public static String createCharacterCard(String data)
```

Не изменяй пакет, класс и сигнатуры методов.

## Примеры

```text
createCharacterCard("Kirill|mage|15")
→ "[MAGE] KIRILL (уровень 15)"

createCharacterCard("  Тёмный рыцарь | маг огня | 7 ")
→ "[МАГ_ОГНЯ] ТЁМНЫЙ_РЫЦАРЬ (уровень 7)"

createCharacterCard("Kirill|mage")
→ "Некорректные данные"
```

## Ограничения

- Аргументы не равны `null`.
- Уровень проверять как число не нужно, но поле не может быть пустым.
- Не используй `split` и циклы.
- Используй `indexOf`, `lastIndexOf`, `substring` и методы обработки строк.

## Критерии готовности

- `normalizeToken` работает отдельно.
- Строка с двумя разделителями разбирается правильно.
- Лишний или отсутствующий разделитель считается ошибкой.
- Пустое поле считается ошибкой.
- Все тесты проходят.
